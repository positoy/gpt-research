# 지속형 리서치 에이전트 실험: 경기광주 개발계획

## 1) 이 프로젝트의 진짜 목표

이 프로젝트의 핵심 목표는 다음이다.

- 지속적으로 새로운 정보를 탐색한다.
- 새로운 정보의 출처와 신뢰도를 평가한다.
- 기존 지식과 비교/융합하여 지식 체계를 갱신한다.
- 이 과정을 자동화하는 에이전트의 원리, 개념, 기술을 체득한다.

즉, 단발성 검색 봇이 아니라 `증거 기반 지식 시스템`을 만드는 것이 목적이다.

## 2) 실험 도메인

위 목표를 실제로 검증하기 위해 다음 도메인을 1차 실험 대상으로 삼는다.

- 경기도 광주 구도심 및 경기광주 개발계획

이 도메인을 선택한 이유는 다음과 같다.

- 문서(고시/공고/보도자료), 지도/공간정보, 거래정보가 함께 존재한다.
- 시간이 지나며 정보가 갱신되고 충돌 가능성이 높다.
- 출처의 권위와 최신성이 판단에 직접 영향을 준다.

## 3) 시스템 설계 원칙

- 원문과 해석을 분리한다.
- 주장(claim)과 증거(evidence)를 분리한다.
- 수집 시각(observed_at)과 사실 유효 시점(valid_from/to)을 분리한다.
- 기존 지식을 덮어쓰지 않고 append-only 버전 기록을 유지한다.
- 모든 판단은 출처 추적 가능해야 한다.

## 4) 에이전트가 풀어야 할 핵심 문제

- 어디서 무엇을 얼마나 자주 수집할 것인가
- 새 정보가 기존 지식을 지지/반박/갱신/중복 중 무엇인지
- 출처 권위, 최근성, 직접성, 교차검증 수를 바탕으로 신뢰도를 어떻게 점수화할 것인지
- 사람이 읽기 쉬운 단일 Markdown 문서를 어떻게 안정적으로 생성할 것인지

## 5) 권장 아키텍처 (역할 분리)

- Control Plane (에이전트)
  - 조사 계획 수립
  - 수집 작업 지시
  - 차이점 분석
  - 재조사 큐 생성
- Data Plane (백엔드/워커)
  - 크롤링/파싱/OCR
  - 정규화/엔티티 추출
  - DB 저장/버전 관리
  - 품질 검증
- Knowledge Plane (지식 저장소)
  - source / document / evidence / claim / revision 관리
- Publishing Plane (문서 생성)
  - 사람이 읽는 최종 Markdown 조립
  - 목차/앵커/출처 색인 자동 생성

## 6) 워크플로우 (요약)

1. 주제 입력 및 조사 범위 정의
2. 소스 맵 작성 (공식/준공식/보조)
3. 수집 실행 및 원문 저장
4. 전처리 및 claim/evidence 추출
5. 기존 지식과 비교 (일치/충돌/신규/갱신)
6. 신뢰도 점수 산정
7. 지식 DB 갱신
8. 단일 Markdown 문서 조립 및 형식 검증
9. 인간 검토 후 발행
10. 재조사 스케줄에 따라 루프 반복

## 7) Frontier 모델 활용 경계

Frontier AI 모델은 다음에 집중한다.

- 주제 트리 구성
- 섹션 초안 작성
- 충돌/누락 후보 탐지
- 비교 요약

코드는 다음을 강제한다.

- 목차/앵커/내부링크 생성
- 중복 헤딩/끊긴 링크/누락 출처 검증
- citation 렌더링 규칙
- 최종 Markdown 조립

원칙은 `AI가 작성`, `코드가 검증`, `사람이 승인`이다.

## 8) 신뢰도 평가 프레임 (초안)

- ★★★★★: 공식 1차 출처 + 최근성 양호 + 독립 교차검증 충분
- ★★★★☆: 공식 출처 중심이나 교차검증이 제한적
- ★★★☆☆: 출처 혼합, 일부 간접 정보 포함
- ★★☆☆☆: 단일 간접 출처
- ★☆☆☆☆: 미검증 추정

별점은 모델의 감각이 아니라 규칙 기반 점수로 계산한다.

## 9) 경기광주 실험의 1차 산출물

- 수집 대상 소스 인벤토리
- 탐색 로그 스키마 (경로/시간/결과/오류)
- claim/evidence/source DB 스키마 초안
- 신뢰도 산정 규칙표 v1
- 단일 `README.md` 형태의 지식 문서 템플릿

## 10) 성공 기준

- 같은 질문에 대해 출처를 역추적할 수 있다.
- 새 데이터 유입 시 어떤 지식이 어떻게 바뀌었는지 설명할 수 있다.
- 신뢰도가 낮은 항목을 자동으로 재조사 큐에 넣을 수 있다.
- 문서가 누적 업데이트되어도 구조와 가독성이 유지된다.

- 버전 가능한 지식 저장소
- 자동 검증 가능한 문서 생성 파이프라인

그리고 이 전체를 `경기도 광주 개발계획`이라는 실제 도메인에서 반복 운영하며 학습한다.
