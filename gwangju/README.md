# 광주 연구 워크플로

## 목표

광주 개발사업 문서를 시간순으로 축적하고, 새 문서가 생길 때만 반영한다.

## 핵심 원칙

- 정기점검 URL을 상시 확인한다.
- 새 내용이 있으면 유의미성을 먼저 판단한다.
- 유의미한 새 내용이 없으면 아무 것도 갱신하지 않는다.
- 유의미한 새 내용이 있을 때만 원문 저장, 추출, 요약, 통합, 커밋을 진행한다.

## 처리 순서

1. 현재 상태 점검
   - 기존 문서 목록 확인
   - 누락된 차수 / 버전 확인
   - 최근 추가된 고시·변경·공고 확인

2. 문서 탐색
   - 정기점검 URL을 확인
   - 새 항목이 있으면 관련성 검토
   - 필요할 때만 상세 페이지와 원문 확보

3. 원본 저장
   - 원문 파일을 `files/`에 저장
   - 가능하면 `YYYYMMDD_한글명` 형식 사용

4. Markdown 추출
   - HWP / HWPX / PDF는 `kordoc` 우선 사용
   - `scripted/{원본과 동일한 이름}.md`로 저장

5. 요약 작성
   - `summary/{원본과 동일한 이름}.md`에 간단한 한국어 요약 저장
   - 무엇이 바뀌었고 왜 중요한지에 집중

6. 통합
   - `report.md`에 문서 메타데이터와 출처 반영
   - `timeline.md`로 시간순 정리
   - `master.md`로 전체 서술 통합

## 출력 원칙

- 원본 문서는 하나당 하나만 유지한다.
- 추출본과 요약본은 별도 Markdown 파일로 둔다.
- 파생 파일은 원본 파일명 기반으로 만든다.
- 가능한 한 정확한 날짜와 차수 정보를 파일명과 요약에 남긴다.
- 정기점검에서 유의미한 새 내용이 없으면 커밋하지 않는다.

## 디렉토리 구조

- `files/` — 원본 문서
- `scripted/` — 추출된 Markdown
- `summary/` — 문서 요약
- `report.md` — 문서 인덱스
- `timeline.md` — 시간순 기록
- `master.md` — 통합 연구 서술
